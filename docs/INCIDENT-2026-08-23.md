## 事件 2：下午 14:43 "卡片渲染错误崩溃"

### 证据链

1. 会话 `dd6a1a26` turn 11 step 27（14:43:48）最后一个工具调用的**完整命令**（日志 seq 95875）：
   ```powershell
   git add -A; git commit -m 'feat(P5): ...' | Select-Object -Last 2;
   $p = Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
        Where-Object { $_.CommandLine -match 'profile feishu' };
   if ($p) { Stop-Process -Id $p.ProcessId -Force; Start-Sleep 2 };
   & D:\dsh-install\start_bridge.ps1; Start-Sleep 10; ...
   ```
   ——上一步流式文本明说计划："最后跑一遍全量回归 + 提交 P5 + **重启真实桥**"。
2. git commit 实际完成（`596e7aa`，COMMIT_EDITMSG mtime 14:43:50）。
3. 会话日志**戛然而止于 tool/call**：没有 tool/result、没有 step/end、没有 turn/end——进程在工具结果落盘前死亡。
4. `bridge.out.log`（stdout）mtime 停在 11:19:28、`bridge.err.log`（stderr）停在 14:35:15，**均无任何崩溃堆栈**——非 JS 未捕获异常（那会打印到 stderr），是 `Stop-Process -Force` 的硬杀。
5. 后续的 `start_bridge.ps1` 从未执行（日志文件未被新进程重写）——执行它的 pwsh 是被杀 node 进程的子进程，**随宿主一同死亡**（Windows 作业对象/管道清理），重启链条断裂。
6. 桥进程死亡 → 流式回合卡片永久冻结在"工作中"状态、approval 卡（另一会话 `123af334` turn 4 在 14:33:30 悬了一个审批）也无人应答——用户侧看到的就是"卡片渲染出错 + 桥没了"。
7. 15:39:31 用户手动重启（现进程 pid 15948）。

### 根因定性

**自杀式重启反模式**：代理运行在桥进程内部，却用"杀掉桥进程再启动"的方式重启桥。杀成功的一瞬间，重启链（自己的子进程）也死了。卡片渲染本身没有 bug（真实事件流 95,877 条全量回放渲染器无异常）。

### 审计中顺带发现的真实隐患（一并加固）

| 隐患 | 后果 | 加固 |
|------|------|------|
| `ctx.on('session/event')` 监听器**无异常隔离**；dsh 的 `session.append()` **同步调用**监听器，任何同步抛错直接穿透到 append 调用方 → 进程级死亡 | 渲染器任意 bug = 桥全挂 | 监听器整体 try/catch，错误落日志 |
| 渲染器 `st.blocks` 可能出现**稀疏空洞**（同一 step 中 tool-call 块位于 text 块之前时，`blocks[i]` 被跳过而高位索引被写入）；`for..of` 会把空洞迭代为 `undefined`，旧代码 `b.kind` 直接 TypeError | 正是能触发上一条进程死亡的真实路径 | 所有迭代点 null-safe；buildTurnCard 先 `filter(Boolean)` |
| 卡片更新失败只置 `dirty=true` 但**不再安排定时器**（turn/end 后无新事件）→ 卡片永久冻结 | 用户看到的"卡住"会再现 | 有界指数退避重试；连续 5 次失败后**换发新卡**兜底 |
| 卡片元素数量无上限，超长回合可能被飞书整卡拒绝（拒绝又叠加上一条 → 永冻） | 同上 | 卡片 div 元素 ≤ 28，超出折叠中段并标注 |
| 桥自身**零持久日志**（stdout 进最小化窗口/随进程消失），事故无现场 | 排障只能靠猜 | 默认 `$DSH_HOME/feishu/bridge.log`（5MB 轮转），启动记录 PID；启动脚本轮转 `.prev` |
| 进程级 uncaughtException/unhandledRejection 无记录 | 静默死亡 | 两类钩子先落日志再按原语义处理 |
| 无安全的进程内重启手段，才逼出自杀式命令 | 本次事故 | ① tools guard 拦截杀宿主命令；② 新增 `/restart`：经 **schtasks 一次性计划任务**在进程外执行"等旧 PID 退出 → 拉新进程"，杀掉自己也不影响重启链 |
