# 事故报告：2026-08-26 10:08 自重启失败（飞书桥停机 14 分钟）

## 概要

飞书桥（dsh-feishu）通过计划任务执行 update-restart 时，新桥进程被创建后立即被
Windows 任务计划程序无声杀死，飞书机器人停机 14 分钟（10:08–10:22），直到用户
手动重启两次才恢复。根因是**计划任务作业对象（Job Object）的生命周期清理杀死了
任务内启动的后台子进程**。已通过"专用桥任务 + 前台运行"架构修复并验证。

## 根因

Windows 任务计划程序为每个任务实例创建一个作业对象。任务动作进程
（`powershell.exe -File restart-now.ps1`）退出、任务实例完成时，调度器关闭作业并
**终止作业内的全部进程**——无论它们是否还有自己的生命周期。

旧 restart-now.ps1 的最后一步：

```powershell
& 'D:\dsh-install\start_bridge.ps1' *>&1 | Add-Content ...
```

start_bridge.ps1 内部用 `Start-Process node ... -PassThru` **后台**拉起桥并立即
返回。于是时序为：

1. restart-now.ps1（任务根进程）调用 start_bridge.ps1 → node pid=14524 创建成功
   （写入了 "new bridge pid=14524" 日志）；
2. start_bridge.ps1 返回 → restart-now.ps1 写 "finished" 后退出；
3. 任务实例完成 → 调度器关闭作业 → **node 14524 被 TerminateProcess 无声杀死**；
4. node 死于初始化早期（未写过任何日志），stderr 为空——现场"零输出、零崩溃记录"。

该机制与现场证据完全吻合：进程被创建（有 pid 日志）但无任何应用层输出；被外部
终止的进程没有机会写崩溃报告。同一 start_bridge.ps1 在**交互终端**手动运行时
（10:22、10:23）新桥全部存活——因为交互会话不在任务作业里。

同构风险：`src/commands.js` 的 `cmdRestart`（飞书 /restart 命令）生成的脚本走同一条
`& launcher` 路径，存在完全相同的缺陷——只是此前 /restart 的实际执行恰好都发生在
交互环境，未暴露。

## 修复（2026-08-26）

核心思路：**桥不再从重启脚本的进程树里拉起，而是作为专用计划任务的根进程前台
运行**——桥活着 = 任务活着 = 作业活着；桥退出 = 任务完成、作业关闭、无残留。
重启脚本只负责"杀旧 + 请调度器启动桥任务"，两者作业互不相交。

| # | 对象 | 变更 |

| 1 | `D:\dsh-install\run_bridge.ps1`（新增） | 前台运行桥的任务宿主脚本：注入桥所需环境变量、轮转 out/err 日志、`cmd /c node ... >> out 2>> err` 字节级保真前台执行、退出码落日志 |

### 顺带修复：脚本编码地雷

修改 restart-bridge.ps1 时发现工具链会把 UTF-8 中文按 GBK 双重编码（"后续启动命令"
→"鍚庣画鍚姩"，并吞掉换行导致语法错误）——该文件历史上有 `.nobom.bak` 前科。
三个计划任务执行的 ps1（run_bridge / restart-now / restart-bridge）已全部重写为
**纯 ASCII**（英文注释），并通过 Windows PowerShell 5.1 真实解析器验证。

### 已知问题（上游，Windows 特有）

- `lib/skills.js` backupSkill 用 `tar -C <abs> -czf <abs> <name>`：Git GNU tar 会把
